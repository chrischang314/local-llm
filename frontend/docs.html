OpenAI-compatible

Use your local models from code.

This app exposes a REST API that follows the OpenAI chat completions shape for model listing, streaming responses, and non-streaming responses.

Base URL

Docker compose exposes the backend on port 8001.

The browser UI uses same-origin paths through nginx. Keep frontend calls relative, such as /v1/models, /github/status, and /agent/jobs.

OpenAI SDK base URL
http://localhost:8001/v1
FastAPI explorer
http://localhost:8001/docs

Chat Completions

POST /v1/chat/completions

Send messages to an Ollama model and receive an OpenAI-style response.

Request Body

Field Type Required Description
model string Yes Model ID, such as llama3.2:3b.
messages array Yes Array of { role, content } messages.
stream boolean No Return server-sent events when true.
temperature number No Sampling temperature.
max_tokens integer No Maximum generated tokens.
web_research boolean No Fetch current web sources and add them to the model context when true.
research_query string No Optional explicit search query. Defaults to the latest user message.

Research responses include X-Research-Status and X-Research-Source-Count headers. When web sources are retrieved, the backend appends a Sources footer with full URLs after the model answer. The chat UI Research toggle applies to one message and then resets.

GitHub Integration

The Code Jobs workspace uses a service-style GitHub OAuth flow. The OAuth App is configured once for Local LLM, then each user clicks Sign in with GitHub and authorizes on github.com.

GET /github/status

Returns whether the OAuth App is configured and whether the current Local LLM user is connected.

Response
{
  "configured": true,
  "connected": true,
  "mode": "oauth",
  "oauth": {
    "configured": true,
    "callback_url": "http://localllm.lan/github/oauth/callback"
  },
  "connection": {
    "auth_type": "oauth",
    "account_login": "octocat",
    "repository_selection": "all-visible-to-token"
  }
}
POST /github/oauth/config

Saves the one-time service OAuth Client ID and Client Secret. These are stored encrypted locally; regular users do not need to paste keys before signing in.

POST /github/oauth/start

Returns a GitHub authorization URL for the current Local LLM user.

Response
{
  "configured": true,
  "auth_url": "https://github.com/login/oauth/authorize?...",
  "callback_url": "http://localllm.lan/github/oauth/callback",
  "mode": "oauth"
}
GET /github/repositories

Repository browsing for the signed-in GitHub user.

Response
{
  "repositories": [
    {
      "full_name": "chris/local-llm",
      "default_branch": "main",
      "html_url": "https://github.com/chris/local-llm"
    }
  ]
}

Code Jobs

Code Jobs are agentic coding tasks launched from the frontend. The UI is defensive: if these routes are not available yet, it shows an unavailable state instead of affecting chat.

GET /agent/jobs

Lists queued, running, and completed jobs.

POST /agent/jobs

Starts a new code job.

Request
{
  "title": "Add repository picker",
  "prompt": "Build the UI and update docs.",
  "repository_owner": "chris",
  "repository_name": "local-llm",
  "base_branch": "main",
  "target_branch": "codex/repository-picker",
  "dispatch": true,
  "metadata": {
    "mode": "implement",
    "run_tests": true,
    "open_pull_request": true
  }
}
Response
{
  "id": "job_123",
  "title": "Add repository picker",
  "status": "queued",
  "repository": {
    "owner": "chris",
    "name": "local-llm"
  },
  "target_branch": "codex/repository-picker"
}
GET /agent/jobs/{id}

Returns the latest status, summary, logs, branch link, and pull request link for a job.

Frontend Routes

The static frontend should not hard-code backend hosts. nginx proxies these backend prefixes from the same origin:

Prefix Used by
/github GitHub connection status and repository picker.
/agent Code Jobs list, create form, and detail panel.
/research Web research status for the signed-in UI.
/v1 OpenAI-compatible API consumers.

Python

OpenAI client
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8001/v1",
    api_key="not-needed",
)

response = client.chat.completions.create(
    model="llama3.2:3b",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "What is Docker?"},
    ],
)

print(response.choices[0].message.content)

JavaScript

fetch
const response = await fetch("http://localhost:8001/v1/chat/completions", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    model: "llama3.2:3b",
    messages: [
      { role: "user", content: "What is Docker?" }
    ],
  }),
});

const data = await response.json();
console.log(data.choices[0].message.content);
